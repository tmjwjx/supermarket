落地了哪三条能力

REGISTER

创建即活跃

写入 ACTIVE 用户，立刻签发 token，回包带公开资料。

LOGIN

校验后同形签发

验号验密通过后，token 字段与注册完全同一套形状。

GET USER

按 id 取公开资料

只回 User，不含密码，也不靠 token 认“我”。

动作 方法 路径 回什么

登录 POST /v1/users/login 同样形状的 token
查资料 GET /v1/users/{id} 公开 User
02

身份规则怎么卡

规则 约束 落点
手机号形态 大陆 11 位，1 开头 边界先拒，用例再拒
手机号唯一 库唯一索引，冲突即占用 写入时映射冲突
密码存储 bcrypt，明文不落库 只留在持久化对象
对外 User 永不带密码或哈希 回包当场拼公开字段
停用账号 登录直接拒绝 验密之前先看状态
注册初始态
一律写成 ACTIVE，没有“待激活”。
空密码
注册、登录都按参数非法拦下。
非法 id
空 UUID 或解不出，按参数非法。
!

登录不暴露号是否存在查不到用户也回无效凭证，不走“用户不存在”，避免用登录接口枚举手机号。

03

失败分别回什么

场景 原因码 语义 谁触发
手机号已占用 PHONE_ALREADY_EXISTS 冲突 注册写入撞唯一
密码不对 / 号不在 INVALID_CREDENTIALS 未授权 登录验密失败
资料不存在 NOT_FOUND 找不到 按 id 查询落空
账号已停用 DISABLED 禁止 登录看到停用态
参数不合法 INVALID_ARGUMENT 坏请求 号、密、id 不合格
i

对外原因码带 USER_ 前缀契约枚举是 USER_PHONE_ALREADY_EXISTS 这一族；上表写短名只为扫读。

04

Token 长什么样

算法
HS256 JWT，密钥来自配置。
subject
sub 只放用户 id，不塞角色。
有效期字段
回包 expires_in_ms，默认 7 天。
默认毫秒
604800000（未配或 ≤0 时）。
注册与登录
同一签发函数，形状不允许分叉。
AUTH.JWT_SECRET

签名密钥

配置键 auth.jwt_secret，开发环境直接写在 yaml 里。

AUTH.TOKEN_EXPIRE_MS

过期毫秒

配置键 auth.token_expire_ms。改这个数，注册和登录的 expires_in_ms 一起变。

05

四层各补了一刀

serviceDTO ↔ DO → biz用例 + JWT → dataGorm + 冲突 → server双协议挂载
层 这刀补什么 不许越界
service DTO↔DO，先校验再交 不碰存储、不写规则
biz 用例、仓库接口、签发 JWT 不认 proto 体、不认表
data Gorm 落库，唯一冲突映射 不拼对外回包
server HTTP/gRPC 同时挂 User 不翻译字段、不写业务
i

Todo 没有拆掉服务端同时挂 User 与既有 Todo。这次是加身份面，不是换掉演示资源。
