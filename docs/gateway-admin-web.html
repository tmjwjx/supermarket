网关与管理台架子

浏览器只跟网关说话。注册和登录公开转到 user；按 id 查用户必须先在网关用 HS256 验过签，失败直接拒绝，不再往下转发。

对外只有 HTTP 8080。 网关把公开的注册、登录原样交给 user 的 gRPC 9000；查用户先做本地验签。管理台目录是 admin-web，令牌放在当次会话的 sessionStorage。
8080网关 HTTP 监听
9000user gRPC 地址

01

两块架子 #

网关是唯一对外入口，管理台是调用它的页面。两边都不自己保存用户资料。

网关

只做入口和验签

进程只装配 HTTP 服务、user 客户端和验签器。配置里只有监听地址、上游地址和 JWT 密钥。

管理台

只做三个表单

目录名 admin-web，页面标题「管理台」。注册、登录、按 id 查资料，请求都走网关。

边界现在的规则
入口只监听 HTTP 0.0.0.0:8080
上游只拨 127.0.0.1:9000
存储不连 MySQL，配置里没有数据库
分层不自建契约、领域和仓库
超时HTTP 与上游各 1 秒
02

三条路由 #

公开的两条把请求体原样交给上游。查用户先过验签，通过后才按路径里的 id 转发。

路由谁能进通过之后
POST /v1/users/register 公开 转发 Register，回 200
POST /v1/users/login 公开 转发 Login，回 200
GET /v1/users/{id} 先验签 转发 GetUser，回 200
  1. HTTP 8080接住三条路由
  2. 注册 / 登录不验签
  3. 查用户先验过才继续
  4. user :9000只收放行的请求
03

本地验签 #

验签发生在转发之前。任一条不满足，都返回未授权，后面的 GetUser 不会被调用。

条件结果
不是 Bearer401，不转发
密钥为空401，不转发
算法不是 HS256401，不转发
解析失败或声明无效401，不转发
sub 为空401，不转发
以上都过才转发 GetUser
拒绝时的错误

原因码 GATEWAY_UNAUTHORIZED，正文 unauthorized。密钥读配置 auth.jwt_secret，与 user 服务同一把，写在 yaml 里。

请求与令牌 #

页面用相对路径调用 /v1。开发时这段路径被转到网关 8080，不另连别的服务。

  1. 页面fetch 相对 /v1
  2. 开发代理只转发此前缀
  3. 网关127.0.0.1:8080
存放
sessionStorage 键名 access_token
写入
注册或登录响应里的 access_token，也认 accessToken
读取
查资料提交时再读一次
请求头
有令牌才加 Authorization: Bearer
基址
空字符串，请求走当前站点的 /v1
没登录也能发出查询

查资料页会标明尚未登录。这种请求不带 Authorization，由网关回 401。
