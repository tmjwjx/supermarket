01这个模块负责什么#

user 是买家身份的唯一来源：发令牌、给资料、管收货地址。它不直接面对浏览器，前端经 gateway 转 gRPC 进来。

账账号

Register / Login：手机号 + 密码，bcrypt 存哈希，签发 HS256 JWT。

资资料

GetMe 按令牌取本人；GetUser 只允许查自己。

址地址簿

增、改、删、列表、设默认，每人最多 20 条，第一条自动为默认。

照地址快照

内部 GetAddress(id, user_id)，order 下单时调用，把地址抄进订单。

03实现逻辑#

身份怎么进来

身份只认验签结果。gateway 验过令牌写入元数据，user 的 service 层用 callerID 读出，再一路以 user_id 条件落到 SQL。

  1. 客户端Authorization: Bearer
  2. gatewayrequireLogin 验签，写 x-md-global-user-id
  3. servicecallerID 解析 UUID，失败 400
  4. biz校验参数与条数上限
  5. dataWHERE id = ? AND user_id = ?

07已知遗留#

并发新建地址不在一个事务

计数、清默认、插入三步各自提交。并发新建可能越过 20 条，首条并发时也可能出现两条默认。

契约地址错误码借用

地址不存在返回 USER_NOT_FOUND，超 20 条返回 USER_INVALID_ARGUMENT。调用方分不清是用户还是地址的问题。

500超长字段不拦

只校验非空和手机号，不限长度。receiver 超 64、省市区超 32、detail 超 255 时，MySQL 严格模式报错原样上抛成 500。

路由自身端口 /me 被抢先匹配

生成代码先注册 /v1/users/{id}。直连 user 的 HTTP 端口请求 /me 会落到 GetUser，得 400。
