01这个模块负责什么#

商品服务是整个超市的「货架」：后台在这里建目录、录商品、走审核，买家在这里逛、搜、收藏、评价。订单下单前向它要 SKU 快照和可售判断，库存靠它发出的事件给新 SKU 建档。

目录底座

品牌、两级分类、属性模板（规格 / 参数）。分类可以绑定模板，商品保存时按模板校验。

商品生命周期

商品 + SKU 录入、审核状态机、改价、批量上下架、回收站与彻底删除，全程留审核记录和操作日志。

买家浏览

列表、搜索、详情、推荐位，以及登录后的收藏、浏览记录和评价。

对外契约

给订单三个 gRPC，给库存 product.sku.created 事件，消费 order.completed 记销量。

02变更点#

按能力和规则列出这次新增的内容，不按文件罗列。

目录底座：品牌、分类、属性模板

品牌 5 RPC

  • 名称唯一；并发同名创建靠唯一索引兜底，也译成 BRAND_NAME_EXISTS
  • UpdateBrand 是 optional 字段补丁，没带的保持原值
  • 仍有商品时不能删；买家只看显示中的

分类 5 RPC

  • 最多两级，父级只能是一级；同父级下重名拒绝
  • UpdateCategory 改名、图标、排序、显示、模板，父级不可改
  • 买家树里隐藏的一级连同子级不出；AdminListCategories 含隐藏

属性模板 7 RPC

  • 属性分规格（kind=1）和参数（kind=2），带可选值和「允许手填」
  • 改属性时可选值非空即整体替换，clear_options 清空
  • 模板被分类绑定时不能删

商品与 SKU 的数据规则

价格
一律整数分（int64）。售价、划线价不得为负；上架时启用 SKU 售价必须大于 0。
规格判重
specs_json 按规格名排序后取 SHA-256 存成 spec_hash。请求内重复或撞上 (product_id, spec_hash) 唯一索引，都返回 PRODUCT_SPEC_DUPLICATED。
模板校验
分类绑了模板时，SKU 的每个规格名必须是模板里的规格，取值要在可选值里，勾了「允许手填」才放行任意值。参数名必须是模板里的参数。
图片与详情
最多 9 张图，第一张当主图；图文详情单独一张表，GetProductDetail 单独取。
冗余价
min_price / max_price 只按启用 SKU 聚合。写路径在事务里用 refreshPrice 从库里重算，不信调用方传的值。

后台运营

审核流 留痕

提交、通过、驳回（必须写理由）都写 product_audits；上下架、删除、恢复写 product_logs。

回收站 可恢复

删除是软删除，SKU 一起软删；恢复回到「下架」；彻底删除物理清掉 SKU、图片、参数、详情。

改价与日志 前后值

单 SKU 改价记 change_price 前后价；整体更新只把改了价的 SKU 写成前后 JSON，没改价就留空。

批量上下架

逐个调用单条上下架，结果分成成功列表和失败列表，失败带原因，不因一条失败整批回滚。

买家侧与对外契约

列表 · 搜索

只列在售。一级分类自动展开子级，可按品牌和价格区间筛；order_by 只认 latest / price / price_desc / sales。

详情

只放行在售和下架，只带启用 SKU，附规格选择器 spec_options；登录用户顺手记一条浏览。

推荐位

同位置同商品唯一；起止时间 0 表示不限，结束须晚于开始；公开列表只留生效期内且在售的。

收藏 · 浏览

重复收藏、取消不存在的都算成功，失效商品标 invalid。浏览记录每人最多 100 条。

评价

向订单核对订单项归属、已完成、商品一致；1–5 星、500 字内；下游故障返回 503。

给订单 · 给库存

BatchGetSkus / CheckSellable / IncreaseSales 仅 gRPC；新 SKU 发 product.sku.created。

i
种子数据走 gRPC
make seed 运行 app/product/cmd/seed，以 seed-admin 身份经 gRPC 建品牌、分类、模板、商品并上架、配推荐位，再调 inventory 的 CreateStock 和 AdjustStock 入库，不直接写库。

03实现逻辑#

商品状态机

状态值和库里的数字一一对应（catalog.StatusDraft 等）。每次变更都是一条带起始状态的条件更新，影响 0 行就判为状态冲突，并在同一事务里写留痕。

环节上架校验 readyPublishProduct
读数据
GetFresh 直读库，不读也不写缓存，避免拿旧快照放行。
起始状态
只接受已通过（4）或下架（6），否则 409 PRODUCT_STATUS_CONFLICT。
完整性
分类存在、是二级、显示中；品牌存在、显示中；至少一张图；至少一个启用 SKU。缺哪项就在错误里列出 missing category brand image sku。
售价
所有启用 SKU 售价 > 0，否则列出出问题的 SKU，返回 400。
库存记录
对每个启用 SKU 调 inventory CreateStock（幂等，缺了就补建）。任何一个失败返回 503 PRODUCT_UNAVAILABLE，不上架。
落状态
SetStatus：WHERE id = ? AND status IN (4, 6)，同事务写 product_logs（前后状态名），提交后删详情缓存。

整体更新的写路径

后台编辑商品走 UpdateProduct。「在售能改什么」必须以锁住的库内状态为准，不能看缓存，所以判断放在仓库事务里以回调执行。

详情缓存

绕过缓存
GetFresh（上架校验）、lockProduct（整体更新）、GetAny（后台编辑，含回收站）都不读缓存。
Redis 不可用
启动时 Ping 不通就把客户端置空，缓存整体关闭，读写照常走库。

18 张表

事件、缓存键与分页

发出事件
product.sku.created，key 为 SKU id，payload {"sku_id","product_id"}；与 SKU 同事务写 outbox_events。
消费事件
order.completed（消费组 product-sales），按 事件id/商品id 去重后加销量。
缓存键
product:detail:{id}，TTL 10 分钟，值是整个商品领域对象的 JSON。
分页
page_token 就是十进制偏移；页大小默认 20，最大 50；多取一条判断有没有下一页。

05关键规则与失败处理#

状态迁移判定表

操作允许的起始状态成功后留痕
SubmitProduct草稿、已驳回待审核product_audits submit
ApproveProduct待审核已通过product_audits approve
RejectProduct待审核，理由非空已驳回product_audits reject + 理由
PublishProduct已通过、下架，且过上架校验在售product_logs publish
UnpublishProduct在售下架product_logs unpublish
DeleteProduct任意未删除回收站product_logs delete
RestoreProduct回收站下架product_logs restore
PurgeProduct回收站物理删除不写新记录
!
不满足起始状态 = 409，不存在 = 404
条件更新影响 0 行时再数一次行：没有这条商品返回 PRODUCT_NOT_FOUND，有但状态不对返回 PRODUCT_STATUS_CONFLICT。20 个并发上架只会成功一次、只留一条日志。

失败场景与返回

场景返回说明
规格重复409 PRODUCT_SPEC_DUPLICATED请求内或唯一索引冲突
规格名或取值不在模板400 PRODUCT_INVALID_ARGUMENT消息为 attribute <名>
挂在一级分类400 CATEGORY_NOT_LEAF商品只能挂二级
在售改分类/品牌/规格结构400 PRODUCT_INVALID_ARGUMENT按锁住的库内状态判断
上架缺项或售价 ≤ 0400 PRODUCT_INVALID_ARGUMENT消息列出缺项或 SKU
上架时补建库存失败503 PRODUCT_UNAVAILABLE状态不变
快照一次超过 50 个 SKU400 PRODUCT_INVALID_ARGUMENT缺失的 SKU 标不可售
品牌/分类仍被使用409 BRAND_IN_USE / CATEGORY_IN_USE分类有子级、回收站商品也算

订单侧返回评价返回说明

07已知遗留#

✓
已修复：并发改价导致冗余价不一致
UpdateSkuPrice 和 UpdateProduct 现在都先 SELECT … FOR UPDATE 锁商品行，再用 refreshPrice 按库里启用 SKU 重算 min/max。TestChangePriceConcurrentKeepsRange 覆盖这一点。

公开库存与明文翻页 暴露面

买家能查到精确库存（inventory 公开 GetStocks，见 05 篇）。page_token 就是偏移数字，可随意构造跳页，深翻页走 OFFSET 扫描。

批量上下架不限数量 性能

ids 没有上限，每条上架都要读库、校验、逐个 SKU 调 CreateStock，一次传很多会拖成长请求。

超长字符串返回 500 错误码

名称 128、副标题 256 等长度只在列定义里；service 不校验，MySQL 报「Data too long」没被映射，最终是 500 而不是 400。
