01

整体架构

#

浏览器只打 gateway，gateway 按路由验令牌后用 gRPC 转给七个服务。每个服务只连自己的库；异步通知走 Kafka。

gRPC服务间同步调用

order →
product 取 SKU · inventory 预占 / 确认 / 释放 · user 取地址
payment →
order 取订单、通知已支付
product →
inventory 建库存 · order 核对评价 · user 取显示名

Kafka异步事件（7 个主题）

product.sku.created
→ inventory 建库存记录
order.completed
→ product 加销量、notification
order.* / payment.refunded
created · paid · cancelled · shipped → notification

08

已知遗留

#
!

下一轮最值得先做的三条

三条都不影响本地跑通，但上线前必须处理。

1gRPC 端口对外监听且信任元数据

现状
七个服务 gRPC 绑 0.0.0.0:900x，身份直接取 x-md-global-*
风险
能连上端口就能冒充任意买家或运营
方向
只监听内网，或加服务间认证

2库存预占与确认偶发死锁

现状
预占先改 stocks 再写预占记录；确认先锁预占记录再改 stocks
风险
同一 SKU 并发下单与支付时一方被 MySQL 回滚
方向
统一加锁顺序，或对死锁错误重试

3模拟支付开关不配置时默认开启

现状
simulate_enabled 缺省按开启处理
风险
线上漏配，登录用户可自己把订单「付掉」
方向
缺省改为关闭，本地配置显式打开
