app/payment · api/payment/v1 · HTTP 8004 / gRPC 9004

支付

payment 自己扮演支付渠道：建单时向 order 核对订单，模拟回调只让「待支付」变成成功或失败，成功后同步通知 order；通知不到就每分钟重试，订单已取消就标成已退款并发 payment.refunded，每天凌晨 2 点再和订单对一次账。
4个 RPC对外契约建单、查单、模拟回调、对账差异列表
5种状态支付单待支付 1 · 已成功 2 · 已失败 3 · 已关闭 4 · 已退款 5
3个后台循环定时任务通知重试每分钟 · 对账每天 02:00 · 发件箱每秒
4类差异对账结果写入 reconcile_diffs，后台按日查询

01这个模块负责什么#

不接真实渠道，渠道流水号自己生成，channel 固定为 mock。以后接真实渠道时，只替换「谁来触发回调」这一层。

gateway买家：/v1/payments后台：/v1/admin/payments/reconcile-diffs
→
payment 服务PaymentUsecaseRetryLoop · ReconcileLoop · Streams
→
order（gRPC 9003）GetOrder 核对订单MarkOrderPaid 通知已付ListPaidOrders 对账取数

收款 新增

一张订单只有一张支付单，金额以订单应付金额为准。

通知 新增

成功后通知 order；失败的留在库里，由循环兜底。

对账 新增

只发现差异、写表、记日志，不自动修复。

03实现逻辑#

一次支付的时序

1建支付单 CreatePayment
取订单
调 order GetOrder，元数据带 x-md-global-user-id，order 只按本人查，非本人即找不到
核对
待支付，且 now < expires_at；否则 409 PAYMENT_ORDER_NOT_PAYABLE
复用
order_id 唯一；并发新建撞唯一键就查回已有的那张
金额
新建和重置都取订单 pay_amount
2模拟回调 SimulatePayment
开关
关闭时返回 404 PAYMENT_NOT_FOUND，和不存在的支付单一样
归属
支付单不是本人的也返回 404
重复回调
不是待支付就原样返回当前状态，不报错
成功时
写 paid_at 和随机 channel_trade_no，只有这次真的改动了才去通知 order
3对账 Reconcile
时间
每天本地时间 02:00，对 now - 24h 那一天，单次 1 分钟超时
两边取数
payment：已成功且 paid_at 落在当天；order：ListPaidOrders 取已支付 / 已发货 / 已完成
写入
SaveDiffs 在一个事务里先删这一天再写，重跑结果一致

05关键规则与失败处理#

建支付单判定

情况返回
order_id 为空400 PAYMENT_INVALID_ARGUMENT
订单找不到（含非本人）409 PAYMENT_ORDER_NOT_PAYABLE
order 不可用503 PAYMENT_UPSTREAM_UNAVAILABLE
订单不是待支付，或已过截止409 PAYMENT_ORDER_NOT_PAYABLE
已有待支付的支付单原样返回
已有已失败的支付单重置为待支付，金额刷新
已有已成功 / 已退款的支付单409 PAYMENT_STATUS_CONFLICT

通知 order 的结果

MarkOrderPaid 返回payment 的处理之后
成功MarkNotified，只改已成功且未通知的行不再重试
ORDER_STATUS_CONFLICTMarkRefunded：已退款、notified = true、写事件不再重试
其它任何错误只记日志 notify order paid下一分钟重试
✓
重试多少次都只改一次订单order 侧对同一支付单的重复通知在已支付、已发货、已完成时都直接成功，详见 06 篇的 MarkOrderPaid 判定表。

07已知遗留#

模拟开关不配置时默认开启 安全

现象
SimulateEnabled 是 *bool，为空时 SimulateOn 返回 true；cfg 为空也按开启
影响
部署时漏配这一项，任何登录用户都能把自己的支付单标成成功

ORDER_NOT_FOUND 被当成下游不可用 重试

现象
orderClient.MarkOrderPaid 除了状态冲突，其它一律映射成 ErrPaymentUpstream
影响
订单确实不存在时 notified 永远是 false，每分钟重试、每分钟打错误日志

对账跨零点会误报 对账

现象
两边各按自己的 paid_at 切日；order 的 paid_at 是收到通知那一刻，晚于支付单
影响
零点前付款、零点后才通知到，两天各报一条差异
